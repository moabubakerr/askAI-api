# Session N — deploy the whole thing and measure it where it runs

Read `AGENTS.md` first (house rules, VM facts, deployment order, build state). This brief adds only
what is specific.

**Run this after Sessions L and M land.** Its whole value is that it is the first session to judge
the engine by what a reader gets on the VM rather than by what the suite says on a developer
machine. Every serious defect found on 2026-09-17 — a country that refused its own question, a
ladder that never ran, an execution layer with one shape — passed the suite and failed a reader.

## What it is not

Not a release checklist. Nothing here is signed off because a command exited zero. Each step ends in
a number or a behaviour that is written down.

## 1. Redeploy

The three commits of 2026-09-17 (`9cd8a3d`, `ca7312f`, `7ef6973`) are **code-only** — no schema, no
ingest change — so they need no `provision` and no `refresh`:

```bash
cd ~/askAI-api && git pull
export RUNTIME_NETWORK=kap_shared_network
export ASKAI_EXPORT_DIR=~/askAI-api/data
docker compose build askai-api
docker compose up -d --force-recreate askai-api
```

`--force-recreate` matters: without it Compose keeps the old container when the service definition
has not changed, and you test the previous image.

**Session M's index build changes this.** Adding it means adding a step to the order recorded in
`AGENTS.md` under "Deployed and verified on the VM". Update that record in the same commit as the
step — it is the file the next deployment reads.

## 2. A working client, before any test question

The obvious `curl` shorthand has bitten twice. Use this; it sets its own header, shows the HTTP
status so a 422 cannot look like a null, and builds the body with `jq` so apostrophes in a question
need no shell escaping:

```bash
ask() {
  local q="$1" lang="${2:-en}" body resp code
  body=$(jq -nc --arg q "$q" --arg l "$lang" '{question:$q, lang:$l}')
  resp=$(curl -s -w '\n%{http_code}' http://localhost:17900/api/ask \
           -H 'Content-Type: application/json' -d "$body")
  code=$(printf '%s' "$resp" | tail -n1)
  if [ "$code" != "200" ]; then
    printf 'HTTP %s  %s\n' "$code" "$(printf '%s' "$resp" | head -n-1 | head -c 200)"; return
  fi
  printf '%s' "$resp" | head -n-1 | jq -r '
    .packages[0] as $p
    | "[\($p.kind)\(if $p.refusal_code then " · "+$p.refusal_code else "" end)] "
      + ($p.elements[0].text // $p.reason // "")'
}
```

## 3. Build the gate that does not exist, then run it

**Read this before assuming `tests/corpus_runner.py` does what you need.** It does not. It compiles
every corpus question against a **deliberately empty catalogue** and asserts the *binder's* own
properties — compiling is total, every field is bound once with its precedence recorded, the same
question compiles identically every run. It never reads the `expected:` field, never executes, and
never checks whether a question is answered.

**So nothing in this repository measures whether questions get answered.** That is why a build that
answered 9 of 95 questions passed every gate for days, and why three reachability defects reached a
VM. Closing that hole is this session's main deliverable, ahead of the deployment itself.

Write it: load every `corpus/*.yaml`, run each question through `answer_question` against a real
ingested estate, and compare the resulting package `kind` — and `refusal_code` where the entry
implies one — with the entry's `expected`. **96 questions**, 95 bilingual: 63 answers, 29 refusals,
4 clarifications.

Report the pass count as a number and the failures as a table of *question → expected → got*. That
table is the deliverable. Then wire it in as a sixth gate so the number cannot silently regress.

Two known traps for that comparison, both measured on 2026-09-17:

- An `answer` package can still be **wrong**. `e1-005` ("What percentage of Qatar's energy is
  generated by solar?") expects a refusal and returns *"Energy was 130.90 Index Points in March
  2026."* — the word "energy" matched a published detail. Comparing `kind` alone will not catch a
  false answer; where an entry records a figure or a detail, assert it.
- Several questions answer a **different question than the one asked** — `e5-012` asks which periods
  are available and gets a figure; `e3-011` asks for growth and gets the level. Both report
  `kind: answer`.

Known before you start, so you do not re-diagnose them:

- **`corpus/epic-10.yaml` entry `e10-002` has no English text at all** — Arabic only. 95 of 96 are
  bilingual. Looks like an authoring slip; confirm and fix or record it.
- The four Epic 9 failures live on the `external`/Combined path. Every corpus question uses the
  default `["approved"]`, so they should not appear here. If they do, say so loudly.

## 4. Check the things a suite cannot

- **Both languages.** Ask the same question in `en` and `ar` and read both. Arabic numerals render
  as `2٫6 %`; confirm the refusals and clarifications read naturally too, not just the answers.
- **Staleness.** `freshness.stale` after a refresh, and what an answer looks like when it is true.
- **Latency.** NFR-3's ~2x Combined baseline is testable because `external.elapsed_seconds` is on
  the wire. Measure it rather than assuming it.
- **No identifier reaches a reader.** Grep every response body for a UUID. Session M's clarification
  work is what makes this passable; this is where it is verified.
