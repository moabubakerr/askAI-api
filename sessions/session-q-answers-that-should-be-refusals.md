# Session Q — six questions that must refuse and do not

Read `AGENTS.md` first (house rules, VM facts, deployment order, build state). This brief adds only
what is specific.

**This is the highest-severity work outstanding.** Every other open session is a missing capability.
This one is the engine asserting something untrue, with the same confidence it uses for a figure it
read off a published row. A reader cannot tell the difference, and a refusal that becomes a false
answer is the one failure this whole architecture — the closed world, `execute/` as the only source
of figures, never substitute — exists to prevent.

They are not one bug. Triage them as at least three.

## 1. `e1-005` — a word inside a question binds an unrelated indicator

*"What percentage of Qatar's **energy** is generated by solar?"* matches the published detail
`Energy` on the single span `energy`, binds it, and answers with an index that has nothing to do
with solar generation.

This is exact-name matching, not retrieval — it fails identically with the ladder off. The span
enumeration is working as designed; what is missing is any check that the matched span is what the
question is *about*. A one-word match inside a longer question naming a different subject is the
case to reason about. FR-39's *never substitute* is the rule in play.

Resist the urge to add a length heuristic without evidence. Whatever rule you land on, it belongs
in `rules/data/` with the measurement behind it, and it must not break the terse questions that
work today (`Inflation`, `Inflation monthly`).

## 2. `e3-009` / `e3-015` — a missing target answered with a definition

The corpus says no target and no baseline are published for the inflation rate. Both questions
return inflation's *definition*. Two things went wrong and both need fixing:

- **The operation is misclassified.** *"What is the target for X"* is a question about a published
  target, not a request for a definition. Same family as *"What is the unemployment rate?"*
  binding `definition` instead of `value` (seen on the VM with the ladder on).
- **A definition is being offered as a substitute for the thing that was asked for.** Even with
  the operation right, answering "what is the target" with "here is what the indicator means" is a
  substitution. When the target is not published, say so — `assemble/change/targets.py` already
  distinguishes `target.not_published`.

A target invented for an indicator that declares none is a published-looking figure with nothing
behind it. Treat this pair as the priority of the three.

## 3. `e1-006`, `e9-002` — "no definition is published" is a refusal, not an answer

Both return `kind: answer` carrying *"No definition is published for …"*. The published layer holds
nothing to answer from, which is a refusal — cause three, *published but has no data*, or cause one
depending on what bound. Labelling it an answer means a client renders it as one and the refusal
counters never see it.

The raw id in that sentence is **Session P's**, not yours. Fix the `kind`; leave the wording.

## 4. `e6-003` — "why" answered with a figure

*"Why was inflation negative in 2020?"* returns the 2020 figure. The corpus expects a refusal
because no analyst commentary covers it. Session K landed the `analysis` table and the fetch by
exact key, so the material now exists — check whether this should refuse or answer from commentary
before changing anything, and coordinate with whoever holds Epic 6.
